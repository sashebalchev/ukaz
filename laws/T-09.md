# T-09 On the laptop, one touch of the named finger signs one list, after the list was sent

**Law.** The laptop signer is a service that holds the laptop key. A request gives it the bytes of the cards. It
computes every hash itself from those bytes, answers with the list, and only then asks the fingerprint reader
for the one finger named in its settings. It signs that list if that finger matches within 30 seconds, and it
writes the request to its log before it signs. Another finger, no touch in time, or a request that arrives
while one is waiting: nothing is signed. One match signs one list: no match is kept for a later request.

**Limit.** The laptop's software checks the finger, and the key lies on the laptop's disk where only root can
read it. A program that became root can sign without you. The list is shown by a program that runs as you, on a
screen that programs running as you can draw on. The phone path (T-10) has neither weakness.

**Why.** `sudo` asks for a finger before any list exists and accepts any enrolled finger, so a touch that was
meant for something else could approve a law.

**Blocked.** A request arrives and the reader reports a match for a different finger than the named one: nothing
is signed. Also blocked: nobody touches the reader for 30 seconds. Also blocked: a second request while the
first one waits for the finger.

**Allowed.** Two cards are sent, the named finger touches the reader, and the answer is one manifest with one
signature that `laws verify` accepts. The log gains one line that lists those two cards.
