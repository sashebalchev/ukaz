# T-11 The signing server cannot approve anything, and it hashes what it shows

**Law.** The signing server holds no key. It computes each card's hash from the bytes it was sent, and its page
shows the card from those same bytes. The list that the phone signs is built by the server from the cards you
accepted on the page, and from nothing else. Nothing that is stored on the server, and no answer that the
server gives, makes `laws verify` pass for a list the passkey did not sign.

**Limit.** Someone with root on the server can change the page, so that it shows one card and asks the phone to
sign another. The signature is then real. Until agents have no root on the server, read the list that
`laws sign` prints on the laptop after a phone signing: it names every card that became approved.

**Why.** Agents deploy the server and are root on it. So it may only carry cards to the phone and signatures
back.

**Blocked.** The server's store is rewritten so that the signature for one list sits next to another list:
`laws verify` fails. Also blocked: three cards are sent and two are accepted on the page: the third is not in
the signed list. Also blocked: a card's bytes are changed on the server after the page showed it: the hash in
the signed list no longer matches the card in the repository.

**Allowed.** Three cards are sent from the laptop, two are accepted on the phone under one signature, and the
laptop receives a manifest with those two that `laws verify` accepts.
