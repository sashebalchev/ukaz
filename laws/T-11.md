# T-11 One signing server: every approval passes through it, and it cannot approve anything itself

**Law.** Every approval is made on a request that waits on the signing server: by the phone's passkey on the
server's page, or by the laptop's fingerprint helper. The server keeps a record of each one. The server holds
no key. It computes each card's hash from the bytes it was sent, and its page shows the card from those same
bytes. The list that gets signed is built from the cards you accepted, and from nothing else. Nothing that is
stored on the server, and no answer that the server gives, makes `laws verify` pass for a list that neither the
passkey nor the laptop key signed.

**Limit.** Someone with root on the server can change the page, so that it shows one card and asks the phone to
sign another. The signature is then real. Until agents have no root on the server, read the list that
`laws sign` prints on the laptop after a signing: it names every card that became approved.

**Why.** You want one place where laws are signed. Agents deploy that server and are root on it, so it may only
carry cards to your finger and signatures back, and keep the record.

**Blocked.** The server's store is rewritten so that the signature for one list sits next to another list:
`laws verify` fails. Also blocked: three cards are sent and two are accepted on the page: the third is not in
the signed list. Also blocked: a card's bytes are changed on the server after the page showed it: the hash in
the signed list no longer matches the card in the repository. Also blocked: a signed list that names a card the
server never held for that request is handed to the server: it refuses it.

**Allowed.** Three cards are sent from the laptop, two are accepted on the phone under one signature, and the
laptop receives a manifest with those two that `laws verify` accepts. Also allowed: the same request is
approved from the laptop with the finger instead, and the server's record shows which of the two approved it.
